# デモ版

> [仕様書の目次](README.md)

デモ版は `demo` ブランチの web のビルドで、rw-demo.studio-takumi.dev に静的に置く（#412）。サーバー・relay・D1 は持たない。ベンチ 100 本（チャンネルごとのプロジェクト）の文字起こしと要約を、録音しないで見られるようにする（#413）。

## 常にデモで動く

- `demo` ブランチのビルドは、URL に関係なく常にデモ（`vite.config.ts` の `__DEMO_BUILD__`。テストでは `false`）。土台はもとの `?demo`（`web/src/api/demo.ts` の `isDemo`）で、`isDemo` を見ている操作はそのまま
- サーバーにはつながない。WebSocket を開かず、HTTP の API も投げない（つながらない表示も出ない）。API は `web/src/api/api.ts` の手前で、同梱したデータから答える（下の「API の代わり」）
- 通信の入口（`web/src/api/endpoint.ts` の `apiUrl`・`wsUrl`）は、デモ版のビルドで呼ぶと例外にする（main を取り込んで `isDemo` を見ずに通信する箇所が増えたら、コンソールのエラーで気づけるように）。直接 `fetch` や `WebSocket` を足すときも `isDemo` を見る
- 同梱するデータがない（CI など）ときは、`?demo` と同じく `mock.ts` のダミーデータで動く。ビルドとテストはデータなしで通る

## データ

- 置き場は環境変数 `RW_DEMO_DATA`（相対パスはビルドを動かすディレクトリから）。中は `home/`（`~/.remote-whisper` と同じ構成）と `replay/`（リプレイ。#416）。省いたときは、リポジトリの隣の `rw-hp-contents/demo`
- `RW_DEMO_DATA` を渡したのに `home/` がなければ、ビルドを止める（データなしで出してしまわないように）。省いて隣にもなければ、データなしでビルドする
- プロジェクト＝チャンネル（名前はチャンネル名＝`project.json` の `path` の最後）。セッション＝ベンチの動画
- ビルド時に読むのは `home/setting.json`（`projectOrder` と、表示する要約を選ぶ `ollama.models` の `overview`・`detail`）と、`home/projects/<ID>/` の `project.json`・`transcript-*.md`・`transcript-final-*.md`・`summary-*.md`・`.tmp/<ID>/live-summary.md`。録音ファイルは同梱しない
- プロジェクトの ID の形には頼らない（サーバーと同じく `[A-Za-z0-9-]+` のディレクトリで、`project.json` があるもの）。`project.json` とセッションには `uuid` が要る（ないとビルドを止める）

## md の読み方

サーバーと同じ結果にする（`web/vite/demoDocs.ts`・`web/vite/demoHome.ts`）。

| サーバー | デモ版 |
|---|---|
| `storage/documents.py` の `parse`（フロントマターは YAML 1.1、日時は文字列のまま） | `parseDoc`（`yaml` の 1.1 から timestamp を外して読む） |
| `storage/session_reader.py` の `parse_transcript_lines` | `parseTranscriptLines` |
| 読めない要約・浄書済み文字起こしは飛ばす | 同じ（ビルドのログに出す） |
| 一覧・行・フロントマターの既定値（`routes/projects.py`・`routes/sessions/read.py`） | 同じ形の JSON をビルド時に作る |

違うところ:

- `files.recording` はいつも `false`（録音を同梱しないため。再生の UI は出ない）
- 置き換え（#176）は浄書済み文字起こしに当てない。置き換えのあるセッションはビルドを止める（ベンチのデータにはない）
- プロジェクトの名前はパスの `\` と `/` のどちらでも区切る（Windows のサーバーと同じ）

確かめ方: 本物のサーバー（`create_app` と `TestClient`）に同じ `home/` を読ませ、下の GET の答えをすべて比べて一致すること（#413 の PR で 941 件）。

## API の代わり

`web/src/api/demoServer.ts` の `DemoServer` が、`GET` にだけ答える。それ以外は `403`（「デモ版では変更できません」）。

| パス | 答え |
|---|---|
| `/api/projects` | プロジェクトの一覧（`projectOrder` の順） |
| `/api/projects/{pid}/context-sets` | 参考資料セット（ベンチは空） |
| `/api/projects/{pid}/sessions` | セッションの一覧（新しいものから） |
| `/api/projects/{pid}/sessions/{sid}` | セッションの行と `transcriptMeta` |
| `.../transcript` | 文字起こし（リアルタイム。アップロードした動画は空） |
| `.../final-transcripts`、`.../final-transcripts/{gid}`（`latest` も） | 浄書済み文字起こし |
| `.../summaries`、`.../summaries/{gid}`（`latest` も） | 最終要約。`latest` は全体概要と要約詳細のモデルの組で選ぶ（サーバーと同じ）。この組は、下の「設定」と同じ値 |
| `/api/settings` | 設定（下の「設定」） |
| `/api/settings/options` | 選べる値。LLM は Ollama で、モデルは qwen3.5:4b / qwen3.5:2b / qwen3.5:0.8b / gemma4:e4b / gemma4:e2b の 5 つ |

ないもの・ない版は、サーバーと同じステータスと文言（`404`・`410`）。ほかのパスは `404`。

## ビルドの形

- `web/vite/demoDataPlugin.ts` が `virtual:rw-demo-data` を作る。一覧（プロジェクトとセッションの行）は最初の JS に入り、セッションの中身（文字起こし・浄書・要約）はセッションごとのチャンク（`demo-session-<番号>-<ハッシュ>.js`）にして、開いたときに読む
- PWA が最初に取っておくのは今までどおり `index-*` だけで、セッションのチャンクは開いたときに取る
- リプレイの記録（下の「リプレイ」）は `demo-replay-<ハッシュ>.js` にして、リプレイのセッションを開いたときに読む

## リプレイ（#416）

実際に録音したときに、文字起こしと要約が進んでいく様子を 1 本だけ再生する。素材は国会の本会議（約 21.5 分）を実時間で流したときの WebSocket のやりとりの記録。

### データ

- `replay/` は、プロジェクトのディレクトリ（`project.json` と md）に、記録（`replay.jsonl`。1 行が `{"t": 秒, "dir": "in" | "out", "msg": …}`）を足したもの。読むのは `web/vite/demoReplay.ts`
- プロジェクト ID は記録の `start`（`dir: "out"`）の `project`、セッションは `started` の `session`。どちらかと `stop` がないとき、ID が `home/` のプロジェクトと重なるとき、セッションが `project.json` にないときはビルドを止める。`replay/` がなければリプレイはない（CI など）
- 一覧では、`home/` のプロジェクトより前（サーバーと同じく、`projectOrder` にないプロジェクトは先頭）。名前は `home/` の国会のプロジェクトと同じ「衆議院インターネット審議中継」なので、同じ名前のプロジェクトが 2 つ並ぶ
- 画面に同梱するのは `dir: "in"`（サーバーから届いたもの）だけ。生成結果（文字起こしが途中で止まる・仮のタイトルに記号が混ざる・政党名が出る など）は直さずにそのまま出す。音声は同梱せず、流さない

### 入口（仮。匠の確認待ち）

`web/src/app/demoReplay.ts` の `DemoReplayEntry` だけで決める（変えるときはここを差し替える）。

- 国会のプロジェクト（`replay/`）に、録音中の形のセッションを 1 つ置く（一覧では録音中の赤い点。タイトルは録音を始めたときと同じく「新しいセッション」）
- 開いたら最初から再生する。最後まで行ったら、終わった状態（最終の要約・浄書済み文字起こしのあるセッション）のまま止まる
- ほかのセッション・何もない画面を開いたら止めて、録音中の形に戻す。もう一度開いたら最初から
- 再生中も、ほかの操作はふつうにできる（止める操作は #414 と同じ）
- 見出しの「ほかの端末で録音中」は、リプレイのセッションでは「録音したときの様子を再生しています」にする。判定はリプレイを始める条件と同じ（`demoReplay` があり、そのセッション。`isReplaySession`）

### 再生のしかた

- WebSocket は開かない。記録のメッセージを、記録の時刻どおりに `connection.receive`（WebSocket で届いたものを受け取っている全員に渡すところ）に流す。画面の受け取り（`serverConnection.ts` の `receive` から先：`Watcher`・`StatusReceiver`・`receiveServerMessage`）は本物と同じ道を通る
- 記録は録音した端末から見たものなので、ほかの端末で録音中のセッションを見る（#238）ときにサーバーが送るものを足す。始めに `watching`（録音中・文字起こしは空）、録音を終えたら `recordingState`（`stopped`）。`stopped` は、サーバーと同じく話している途中だった最後の区間の final を送り終えてから（`stop` の後に届いた最後の final・partial の直後。なければ `stop` の時刻）流す（`watchStoppedAt`）。partial・final・途中の要約は `Watcher` が `applyLiveMessage` で入れる
- 待つ時間は、再生を始めた時刻から測る（`web/src/features/replay/replayPlayer.ts`。遅れても積み重ならず、遅れた分はまとめて流して追いつく）
- 途中で閉じたら、それ以降は流さない。見ている状態は `recordingState`（`stopped`）で、GPU の表示は何もしていない `status` を流して消し、作成中の最終要約も消す
- 録音を終えた後（最終の文字起こし・最終要約・最終のタイトル）は、本物と同じく API を取り直して出す。そのため、`finalTranscript`・`status` の `summarizing`・最終要約ができたときの取り直しは、`isDemo` ではなく `usesMockData`（ダミーのデータのときだけ）で止める

### API の答え（`web/src/api/demoReplayView.ts`）

`DemoServer` は、リプレイのセッションの一覧の行と中身を、再生した時刻のときにサーバーが返していたはずの形で答える（取り直したときに、先の結果が出てしまわないように）。

| 再生した時刻 | 一覧の行 | 中身 |
|---|---|---|
| 再生していない・`stopped` を流すまで | 録音中（`status: recording`、終わりの時刻・長さなし）。タイトルはそこまでに届いた仮のタイトル（なければなし） | 文字起こしはそこまでに届いた final の行。途中の要約はそこまでにできたもの。浄書・最終要約はなし |
| `stopped` を流してから最終のタイトルまで | 録音を終えた行（タイトルは仮のもの） | 文字起こしはファイルのまま。浄書は `finalTranscript` が届いてから。最終要約はまだなく、途中の要約を出す |
| 最終のタイトルが届いた後・最後まで | 同梱したまま | 同梱したまま |

確かめ方: 再生の仕組みと入口は偽の時計のテスト（`replayPlayer.test.ts`・`demoReplay.test.ts`・`demoReplayView.test.ts`）。実時間の 21 分は待たない。画面は Playwright の時計（`page.clock`）を早めて撮る

## 要約

- 要約は qwen3.5:4b と gemma4:e4b の両方を、要約の版として出す（版の切り替えはふだんの画面のまま）
- 既定は gemma（同梱した設定の全体概要・要約詳細が gemma4:e4b のため）。ここは設定の画面・右上のモデルと同じ値を見る（下の「設定」）
- 要約の先頭の出典の行（「この要約は〜から生成されています。」と URL）はデータ側に入っている。画面・パーサーは触らない

## 止める操作（#414）

データを変える操作は、押したらトースト（`toast.info`）で「デモ版のため〜はできません」と出して止める。サーバーには投げず、画面のデータも変えない。

- 入口は `web/src/app/demoGuard.ts` の `blockInDemo(操作)`。デモ版なら文言を出して `true` を返すので、呼ぶ側はそのまま戻る。文言の「〜すること」は同じファイルの `DEMO_ACTIONS` にまとめる（止める操作を足すときもここに足す）。同じ文言のトーストは 1 つにまとめる
- 止めるのはデモ版のビルド（`isDemoBuild`）だけ。`?demo`（説明用のスクリーンショット）では止めない（`web/scripts/screenshots.mjs` が録音・移動・コピーなどを手元だけで動かして撮るため）。`?demo` での今までの動き（`isDemo` を見て手元だけで変える）はそのまま
- 止める場所は、なるべくストアのアクションの入口（`features/*/…Actions.ts`・`recorder.ts`）。ボタンを押しただけで画面が開くもの（共有・参考資料）は、開く前に止める。モデルのページは開ける（#415。中の変更を止める）

| 操作 | 止める場所 | 文言 |
|---|---|---|
| 新規プロジェクト | 作成の画面（フォルダ選び）までは進める。「このフォルダで作成」で止める（`createProject`） | 新たにプロジェクトを作成すること |
| サイドバーの ＋ | `newSession`。URL（`/p/<ID>/new`）を直接・戻る進むで開いたとき（`openNewSession`）は、トーストを出さずに開かない（選択はそのまま） | 新たにセッションを作成すること |
| 録音・続きから録音 | マイクのボタン（何を開いていても）・`startRecording`・`continueRecording` | 録音すること |
| 音声ファイルのアップロード | `uploadAudio`・`pickAudioFiles`・`uploadSources` | 音声ファイルをアップロードすること |
| セッションの移動（ドラッグ） | `moveSession`（離すと元の場所に戻る） | セッションを移動すること |
| プロジェクトの並べ替え | `reorderProjects`（同上） | プロジェクトを並べ替えること |
| 要約の再生成 | `regenerateSummary` | 要約を再生成すること |
| 浄書・浄書済み文字起こしの再生成 | `regenerateFinalTranscript`（録音がないので、ボタンはもともと出ない） | 浄書済み文字起こしを再生成すること |
| 置き換え（修正） | `addCorrection`・`removeCorrection`（本文を選べないので、入力欄はもともと出ない） | 文字起こしを修正すること |
| 用語リスト | 入力欄で足すとき・`addTerm`・`rejectTerm` | 用語リストを変更すること |
| 参考資料 | 右上の「参考資料」を押したとき（開かない）・`changeContextSelection`・`createContextSet` | 参考資料を変更すること |
| 設定の値 | 設定の画面で、表示の設定以外の Select・スイッチ・入力欄・ボタンを変えたとき（下書きは変えない） | 設定を変更すること |
| 通知 | 設定の「最終要約の通知」を切り替えたとき | 通知を設定すること |
| コピー・共有 | 要約の「コピー」・「共有」（共有の画面を開かない） | コピーすること |

ないもの・出ないもの:

- 名前の変更・削除は、今の画面にない（spec/README.md 1 章）。ログイン・ペアリング・アカウントはクラウド版だけで、デモ版のドメインはクラウド版ではないので出ない
- 「はじめに」（#291）は `isDemo` で出さない。お知らせのバナーは、`isDemoBuild` で出さない（もともとクラウド版だけ）

## 設定（#415）

設定の画面は開ける。値は同梱した `setting.json` で、表示の設定だけ変えられる。

- 値: ビルド時に `setting.json` の `whisper`・`ollama`・`llm`・`recording`・`retentionDays`・`materials`・`display` を `DemoIndex.settings` に入れる（クラウド版・8000 番を開ける名前・並び順は入れない）。画面では `web/src/api/demoSettings.ts` が画面の既定値に重ねて `/api/settings` の答えにする。要約の既定の版（`summaries/latest`）・設定の画面のモデル・右上のモデルは、この同じ値を見る
- ベンチの `setting.json` は `cloud.relayUrl` が空文字で、サーバーの検証では読めない。デモ版は `cloud` を見ず、既定値のままにする（データ側は直さない）。`setting.json` に足りない項目も既定値になる
- 同梱したデータがないとき（`?demo`・CI）は、今までどおりダミーの設定
- 変えられるのは表示の設定の 3 つ（サイドバーの録音日時と長さ・用語リスト（文字起こし抽出）の表示・話者の表示）とテーマ。保存を押すと画面に反映し、`localStorage`（`rw-demo-display`）に残す。サーバーには送らず、ほかの項目は保存しない（`web/src/features/settings/demoDisplay.ts`）。テーマは今までどおり端末ごと（localStorage）
- マイクのショートカットは変えられない（ほかの設定と同じく止める）
- 設定のほかの項目は、Select は選択肢を開けるが、選ぶと止めて値を変えない。スイッチ・入力欄・ボタンも同じ。文言は「デモ版のため設定を変更することはできません」
- 「モデル」のページは開ける（右上の「モデル」・設定のタブ・URL `/settings/models` のどれからも。#414 では右上のボタンで止めていたが、#415 で変えた）。中のモデルの Select は 5 つの選択肢を開けて、選ぶと「設定を変更すること」で断り、値は変えない。「おすすめに戻す」も同じ。このページには、ダウンロード・削除・導入・LM Studio への接続のような「取ってくる」操作はない（モデルが入っているかも、サーバーに見に行かず、同梱した選択肢から決める）
- セットアップ（ホストの準備）のタブは出さない（`/settings/setup` は最初のページ＝モデルを開く）。ホストの状態を見に行くと 404 のエラーが見えるため

## 注意書き・バージョン・隠すもの・コピー対策（#414）

- 最初のページ（何も選んでいないとき）は、見出しはそのままで、下の灰色の文字を注意書きにする（`EmptyState`。文面は 2026-11-11 に合意し、2026-11-19 に #422 で書き換えた）。著作権法の条項は書かない。書くのは、デモ版であることとできないこと、リプレイの開き方（リプレイのプロジェクト名とセッション名は `demoReplay.ts` の定数 `REPLAY_PROJECT_NAME`・`REPLAY_SESSION_TITLE`。変えたら注意書きも変わる）、ほかのセッションはベンチマークの生成結果で「文字起こし」「要約」のタブで切り替えること、生成元は公開されている動画（国会は全文・ほかは一部。元の動画は要約の冒頭のリンク）、政治的な立場を示さないこと。スマホの幅では一覧が隠れるので「一覧（スマホは左上のボタンで開きます）」（開くボタンは文字のないサイドバーのアイコン）と書く
- バージョンを出しているところ（設定の左下の `VersionInfo`）は「Ver1.0.0 をもとにしたデモ版」（`web/src/app/version.ts` の `demoVersionLabel`）
- 録音しないので変になるものは出さない: 文字起こしタブの「待機中」、「録音ファイルがないため、再生成できません」（録音を同梱しないので、どのセッションにも出てしまう）。マイクのボタンは出したまま、何を開いていても押せない見た目（灰色のマイク。上の「押すと新しいセッション」などの説明は出さない）にして、押したら止める（録音できないことが分かるように）
- 文字起こしの本文と、要約タブの中身は `user-select: none`（と iOS の長押しのメニューなし）。技術的には回避できるのは承知の上
