# 8. 画面のイメージ

> [仕様書の目次](README.md)

- ChatGPT や Claude に近い、シンプルな見た目（shadcn）。
- 左にサイドバーがあり、プロジェクトごとに過去のセッションを並べる。Ctrl+B で開閉できる。
  - 全体設定の `display.sessionMeta` をオンにすると、セッションのタイトルの下に、録音日時と長さを小さく出す（例: `10/11 14:05 · 1:23:45`）。録音中のセッションは、長さの代わりに「録音中」と出す。長さは `durationSec`、記録がない古いセッションは開始と終了の日時の差。オフ（既定）なら、タイトルだけ。
- サイドバーのプロジェクトの ＋ を押すと、そのプロジェクトの新規セッション画面を開く。録音はまだ始めない。録音を始める前に、モデルや参考資料を選び直せるようにするため。
- サイドバーのセッションを、ほかのプロジェクト（見出しか一覧の中）へドラッグすると移せる（#172。5.4 節）。マウスは少し動かしたら、指（スマホのシート）は長押ししてからドラッグが始まる。離せるプロジェクトは、上に来ると色が付く。同じプロジェクトの中で離しても何もしない（並びは録音日時順のまま）。
  - 移せないセッション（録音中・処理中など）はドラッグを始められず、マウスを乗せると Tooltip で理由を出す。
  - 移したら「『<タイトル>』を<プロジェクト名>へ移しました」と出す。開いているセッションを移したら、移した先で開いたままにする（URL は変わらない）。
- サイドバーのプロジェクトの見出しをドラッグすると、プロジェクトを上下に並び替えられる（#173）。離したら並び順を保存し（5.3 節の `projectOrder`）、ほかの端末にも反映する。録音中でもできる。セッションは並び替えられない（録音日時順のまま。セッションのドラッグは別のプロジェクトへ移すだけ）。
  - セッションのドラッグ（移す）と同じ仕組みで、ドラッグの種類で見分ける。セッションをドラッグしている間はプロジェクトの並び替えの枠を、プロジェクトを並び替えている間はセッションを離す枠を、それぞれ無効にする。
  - マウスは見出しのどこからでも、少し動かしたら始まる。指（スマホのシート）は長押ししてから始まる。見出しの名前の横に握り（マウスを乗せたときに出る）があり、キーボードはこの握りにフォーカスして Space で持ち上げ、上下の矢印で動かし、Space で離す（Esc で取り消す）。セッションをキーボードでドラッグすることはできない（Space は選ぶ操作のまま）。
  - 新しく作ったプロジェクトは、並び順にないので先頭に出る。
- メイン画面の中央下にマイクボタンがある。押したときの動きは、開いている画面によって変わる。
  - 新規セッション画面: 録音が始まり、音量に合わせてアニメーションする。
  - 既存のセッションを開いているとき: ＋ のボタンになり、押すと同じプロジェクトの新規セッション画面を開く（録音は始めない）。ただし、そのセッションを録音し終えてから `recording.continueWindowMin` 分の間は「続きから録音」のボタンになる（#174。6.7 節）。
  - プロジェクトを選んでいないとき: 押せない。
- 録音中は、マイクボタンで一時停止・再開する。録音の終了は取り返しがつかないので、横の小さい録音停止ボタンに分ける。
- 文字起こしは、文字送りの演出で流れるように表示する。
- 画面上部の切り替えタブで「文字起こし」と「要約」の表示を切り替える。
- 録音を終えたセッションで録音ファイルが残っていれば（`files.recording`）、切り替えタブの下に再生バー（ブラウザの audio）を置き、一緒に上に貼り付ける。文字起こしの行の時刻を押すと、その位置から再生する。録音中のセッションと、録音ファイルが消えた（保存期間を過ぎた・変換前）セッションでは、再生バーを出さず、時刻も押せない。読み込めなかったとき（開いた後に消えたなど）も再生バーを消す。
- 浄書済み文字起こし（6.9 節）があれば、文字起こしのタブではそれだけを出す（要約と同じ。リアルタイム文字起こしに戻す切り替えはない）。なければ（録音中・作っている途中・作らない設定・作れなかったとき）リアルタイム文字起こしを出し、作り終えた瞬間に浄書済み文字起こしに替わる（#145）。横に、使ったモデル・話者の数・作った日時を出す。話者を分けた行は、全体設定の `display.showSpeakers`（既定はオフ、#146）がオンのときだけ「話者 1」などを色付きの札にし、話者の数も同じときだけ出す（オフでも文は出し、選んで直せるのは文の部分だけ）。話者分けのモデルを使えなかったときは、そう書く。どちらの文字起こしでも、文字を選んで正しい語に直せる（6.13 節）。作っている間（`status` の `transcribing` に入っているか、GPU キューに `finalTranscript` のジョブがあるとき）は「浄書中…」（再生成のときは「浄書済み文字起こしを再生成しています…」）と出す。
- **浄書済み文字起こしの再生成（#124）**: 要約の再生成と揃える。録音を終えていて録音ファイルが残っているセッションに「<今の Whisper のモデル> で再生成する」ボタンを出す（浄書済み文字起こしがまだなければ「浄書する」）。WhisperX のないサーバー（`/api/settings/options` の `whisper.finalTranscript` が false）では出さない。録音ファイルがなければ、再生成できない理由を出す。版が複数あれば、選んで切り替えられる。既定は、今の全体設定の Whisper のモデルで作ったうちいちばん新しいもの（なければモデルを問わずいちばん新しいもの）。表示しているものが今のモデルのものでなければ「<モデル> の浄書済み文字起こしはまだありません」と出す（モデルを変えても、要約と違って自動では再生成しない。数分かかるため）。再生成したら、要約も再生成するかをトーストで聞く（勝手には再生成しない）。録音中や、ほかのジョブを実行している間に押しても、録音が終わってから・キューの順番で作る。
- 再生しているとき、再生位置に当たる文字起こしの行（始まりの時刻が再生位置以前の最後の行）を目立たせ、その行が画面の中ほどに来るように追う（#122）。再生中に自分でスクロール（ホイール・タッチ・キー。入力欄やダイアログの中の操作は除く）したら追うのをやめ、「再生位置に戻る」ボタンを出す。シーク（行の時刻を押す・再生バーで動かす）したら、また追う。一時停止しても、その位置の行は目立たせたまま。再生する前は目立たせない。
- 右上にモデルなどの簡易設定（参考資料メニューを含む）を置く。簡易設定のモデルは全体設定をそのまま書き換える。参考資料メニューはプロジェクトの `selection` を書き換える（5.4 節）。
  - 簡易設定は「モデル」と参考資料メニューの2つだけ（#179）。「モデル」のボタンには今の要約詳細のモデルの名前を出し、押すと設定モーダルの「モデル」ページ（`/settings/models`）が開く（戻るで閉じる）。要約度は設定モーダルの「要約」にだけ置く。
  - 「モデル」ページには、大きな段階（参考資料・リアルタイム文字起こし・浄書済み文字起こし・リアルタイム要約・最終要約）ごとに、処理とそれに使うものを並べる。Ollama と Whisper は選べ、Silero VAD・wav2vec2・pyannote など選べないものも薄い文字で出す。選べるものの横におすすめのモデルと、Ollama に入っていなければ「入っていません」を出し、「おすすめに戻す」で Ollama のモデルだけをおすすめに戻す。録音中は Whisper のモデルだけ選べない。
- 上のバーの左に、GPU インジケータを小さく出す（使用率と、待っているジョブの数。何か実行中なら点が光る）。押すと、実行中のジョブと経過時間、待っているジョブ（実行する順）が開く。録音中でも見られる。
- 録音中に、要約などのジョブが GPU を使っていて、このセッションの文字起こしがその後ろで待たされているときは、文字起こしの画面の下の状態に「リアルタイム要約の生成中のため、文字起こしを待っています…」のように出す。
- 全体設定はモーダルで開く。
- **画面の URL（#177）**: 開いているものを URL に出し、戻る・進む・再読み込み・URL を直接開く（別の端末に送るなど）のどれでも同じ画面を開く。
  - `/s/<セッションの UUID>`: セッション。プロジェクトを入れないので、セッションを別のプロジェクトへ移しても URL が変わらない
  - `/p/<プロジェクトの UUID>/new`: 新規セッション画面（`/p/<UUID>` も同じ）
  - `/settings/<ページ>`: 設定モーダル（`whisper`・`models`・`ollama`・`storage`・`materials`・`display`。知らないページは最初のページ）。閉じたら開く前の URL に戻る。URL から直接開いたときは、閉じると何も選んでいない画面（`/`）になる
  - セッションを選ぶ・新規セッション画面を開く・設定モーダルを開くと、履歴が増える。設定モーダルの中のページの切り替えと、録音を始めて新規セッション画面がそのセッションになったときは、履歴を増やさずに置き換える
  - 存在しない UUID や、保存期間を過ぎて一覧から消えたものは「見つかりません」と出す（URL はそのまま）
  - `?demo` などのクエリは残す。UUID のないもの（古いサーバー・`?demo` のダミーデータ）は、UUID の代わりに今の ID を使う
  - PWA の service worker は、画面の URL（`/api`・`/ws` 以外）にも `index.html` を返すので、オフラインでも開ける
- **録音中にできないこと（#133）**: 録音中でも、新規プロジェクトの作成・ほかのセッション（または新規セッション画面）を開く・要約のモデルと要約度・設定の多くは変えられる。ほかのセッションを開いている間も、録音中のセッションの文字起こし・リアルタイム要約・用語リスト（文字起こし抽出）は届き続け、戻ると全部そろっている。録音中にできないのは次のものだけで、押せなくして理由を出す（設定画面では項目ごと）。
  - 全体設定のうち、文字起こしのモデル・区切り・マイクの処理（5.3 節）
  - 参考資料メニュー（右上）: 使う参考資料は録音を始めたときに決まり、参考資料の作成は GPU を長く使うため
  - ほかのセッションの浄書済み文字起こし・最終要約の再生成: GPU キューは実行中のジョブを止めないので、再生成している間はリアルタイム文字起こしが止まるため
  - ほかのセッションの「続きから録音」
- 録音中にほかのセッション（または新規セッション画面）を開いているときは、マイクボタンを「録音中のセッションに戻る」ボタンにする（Tooltip は「『<タイトル>』で録音中です。クリックで戻ります」）。一時停止ボタンと録音停止ボタンと録音の状態の表示は、録音中のセッションの画面でだけ出す。サイドバーの録音中のセッションには赤い点を出す。
- スマホ（幅 768px 未満）でも使える。
  - サイドバーは画面に重なるシートになり、左上のボタンで開く。セッションを選ぶと閉じる。
  - 上部の簡易設定は、シートにまとめず、「モデル」と参考資料メニューのボタンをそのまま並べる。
  - マイクボタンは少し小さくし（96px）、画面の下端（ホームバーなど）を避けて置く。
  - タッチではツールチップが出ないので、待機中はマイクボタンの上に短い説明を、録音中は録音停止ボタンの下に「終了」を出す。
  - 設定モーダルは、カテゴリを上に横並びにし、各項目は入力欄を説明の下に置く。
  - 実機（iOS Safari・Android Chrome）での録音は HTTPS が要るので、確認は 7.4 の HTTPS の手順の後。
- ライトとダークのテーマがある。既定は OS の設定（`prefers-color-scheme`）に従い、サイドバーの下のボタンで「OS に合わせる / ライト / ダーク」を切り替えられる。テーマは端末ごとの好みなので、`setting.json` ではなくブラウザ（localStorage）に保存する。録音中でも切り替えられる。読み込み時のちらつきを防ぐため、画面を描く前にテーマを当てる。
- 画面は PWA にする（#104）。ホーム画面に追加すると、単独のアプリとして開ける（HTTPS か `localhost` のときだけ）。
  - service worker が置いておくのは画面だけ。入れたときに、画面の骨組み（`index.html`・最初の JS と CSS・アイコン・録音の worklet）を取っておく。残りの JS（コードの色付けの言語など、ハッシュ付きの名前）は、使ったときに取って置いておく（最大 400 個・30 日）。API（`/api/`）と WebSocket（`/ws`）は置いておかず、いつもサーバーに聞く。
  - 新しいバージョンの画面が入ったら「新しいバージョンの画面があります」と知らせ、「更新」で読み込み直す（録音中は押せない。録音を終えてから）。新しいバージョンは 1 時間ごとと、サーバーのバージョン（7.1 節）が画面と違うとき（サーバーを更新した）に確かめる。入れたときに取っておいた古いバージョン（骨組み）は、更新したときに消す（使ったときに取って置いたものは、ハッシュ付きの名前なので古いものが残っても困らず、400 個・30 日で消える）。古いバージョンの画面のまま、サーバーではもう消えた JS を読もうとして失敗したら（サーバーの画面をビルドし直した後）、読み込み直すように知らせる。
  - アイコンは仮のもの（音声の波形）。
- **常駐アイコン（Windows のタスクトレイ。#135）**: サーバーを常駐させたとき、黒いコンソールの代わりに、常駐アイコンで状態を見る。
  - アイコンは画面（PWA）のものを縮めず、トレイ専用に描く（#144）。背景は透明で、画面と同じ波形の棒を、16px でも潰れない太さで描く。16・20・24・32・48px（Mac は 36px を 18pt として）をそれぞれ描き、OS に縮めさせない（Windows は複数サイズ入りの ICO を作り、表示スケールに合うサイズ［100% で 16、150% で 24 など］で読む。サーバーは DPI 非対応なので、調べる間だけ DPI 対応にして聞き、取れなければ 16。差し替えが失敗したら pystray 標準の出し方に戻し、トレイのせいでサーバーは止めない。Mac の明暗の判定は数秒に 1 回）。棒の色は、タスクバー・メニューバーが暗ければ白、明るければ濃い灰にする（1 秒ごとの状態確認のときに見て、変わったら描き直す）。
  - 棒の色は変えず、右上に白い縁つきの丸い点を打ち（16px でも見える大きさ）、その色で状態を示す。灰: 待機中 / 青: GPU が処理中（GPU キューに実行中か待っているジョブがある）/ 赤: 録音中 / 橙: Whisper か Ollama が使えない。重なったら、橙・赤・青の順に優先する。
  - マウスを乗せると「録音中 1件 / 待ち 3件 / 実行中: 文字起こし」のように出す（Windows は 128 文字まで）。使えないものがあれば、その理由も足す。
  - 左クリックで画面をブラウザで開く。キューの一覧は画面（GPU インジケータ）で見るので、トレイ用の画面は作らない。右クリックのメニューは「画面を開く / ログのフォルダを開く / 終了」。録音中に終了しようとしたら確認を出す。終了は、後片付け（録音を閉じる・GPU キューを止める・Whisper を下ろす）をしてから止まる。
  - 状態はサーバーの中（status）から直接読む（HTTP で取りに行かない）。
  - `remote-whisper-gui`（pythonw）で起動すると、コンソールを出さずにトレイだけで動く。ログはファイル（6.10 節）で見る。`--no-tray` で出さない。
- **常駐アイコン（Mac のメニューバー。#136）**: Windows のトレイと同じ点の色・文・メニューを、メニューバーに出す。`--mock` でも出る（GPU なしで見た目を確かめるため）。`--no-tray` で出さない。
  - Mac の pystray（AppKit）はメインスレッドで動かす必要があるので、Mac ではサーバー（uvicorn）を別のスレッドで動かす（Windows はサーバーがメインスレッド）。メニューバーを出せないとき（画面のない SSH から起動したなど）は、サーバーだけ動かし続ける。
  - アイコンはテンプレート画像にしない（白黒にされず、点の色が見えるように）。
  - マウスを乗せたときの文は出ないことがあるので、メニューの一番上に状態の行（押せない）を出す。
  - 録音中に終了しようとしたときの確認は、AppleScript のダイアログ（`osascript`）で出す。
- Linux では出さない。
