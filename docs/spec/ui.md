# 8. 画面のイメージ

> [仕様書の目次](README.md)

- ChatGPT や Claude に近い、シンプルな見た目（shadcn）。
- 左にサイドバーがあり、プロジェクトごとに過去のセッションを並べる。Ctrl+B で開閉できる。
- サイドバーのプロジェクトは、見出しを押すと閉じる（もう一度押すと開く）。閉じたプロジェクトは端末ごと（localStorage。クラウド版ではホストごと）に覚え、開き直しても閉じたままにする（#318）。覚えるのは閉じているものだけで、新しいプロジェクトは開いて出る。今ないプロジェクトの分は、次に開閉したときに忘れる。閉じているプロジェクトのセッションを開いたとき（URL・通知・ジョブの一覧から）は、そのプロジェクトを開く（覚えている開閉は変えない）。開いているセッションが変わったときだけで、スマホでシートを開き直したときは開かない。
  - 全体設定の `display.sessionMeta` をオンにすると、セッションのタイトルの下に、録音日時と長さを小さく出す（例: `10/11 14:05 · 1:23:45`）。録音中のセッションは、長さの代わりに「録音中」と出す。長さは `durationSec`、記録がない古いセッションは開始と終了の日時の差。オフ（既定）なら、タイトルだけ。
- サイドバーのプロジェクトの ＋ を押すと、そのプロジェクトの新規セッション画面を開く。録音はまだ始めない。録音を始める前に、モデルや参考資料を選び直せるようにするため。
- サイドバーのセッションを、ほかのプロジェクト（見出しか一覧の中）へドラッグすると移せる（#172。5.4 節）。マウスは少し動かしたら、指（スマホのシート）は長押ししてからドラッグが始まる。離せるプロジェクトは、上に来ると色が付く。同じプロジェクトの中で離しても何もしない（並びは録音日時順のまま）。
  - 移せないセッション（録音中・処理中など）はドラッグを始められず、マウスを乗せると Tooltip で理由を出す。
  - 移したら「『<タイトル>』を<プロジェクト名>へ移しました」と出す。開いているセッションを移したら、移した先で開いたままにする（URL は変わらない）。
- サイドバーのプロジェクトの見出しをドラッグすると、プロジェクトを上下に並び替えられる（#173）。離したら並び順を保存し（5.3 節の `projectOrder`）、ほかの端末にも反映する。録音中でもできる。セッションは並び替えられない（録音日時順のまま。セッションのドラッグは別のプロジェクトへ移すだけ）。
  - セッションのドラッグ（移す）と同じ仕組みで、ドラッグの種類で見分ける。セッションをドラッグしている間はプロジェクトの並び替えの枠を、プロジェクトを並び替えている間はセッションを離す枠を、それぞれ無効にする。
  - マウスは見出しのどこからでも、少し動かしたら始まる。指（スマホのシート）は長押ししてから始まる。見出しの名前の左に握り（マウスを乗せたとき・フォーカスしたときに出る。見えないときも幅は取ったままで、名前の位置は動かない。#234）があり、キーボードはこの握りにフォーカスして Space で持ち上げ、上下の矢印で動かし、Space で離す（Esc で取り消す）。セッションをキーボードでドラッグすることはできない（Space は選ぶ操作のまま）。
  - 新しく作ったプロジェクトは、並び順にないので先頭に出る。
- メイン画面の中央下にマイクボタンがある。押したときの動きは、開いている画面によって変わる。
  - 新規セッション画面: 録音が始まり、音量に合わせてアニメーションする。
  - 既存のセッションを開いているとき: ＋ のボタンになり、押すと同じプロジェクトの新規セッション画面を開く（録音は始めない）。ただし、そのセッションを録音し終えてから `recording.continueWindowMin` 分の間は「続きから録音」のボタンになる（#174。6.7 節）。
  - プロジェクトを選んでいないとき: 押せない。
- 録音中は、マイクボタンで一時停止・再開する。録音の終了は取り返しがつかないので、横の小さい録音停止ボタンに分ける。
- **マイクボタンのショートカット（#236）**: キーボードのショートカット（既定は `Alt+Shift+M`、Mac は `⌥⇧M`）を押すと、マイクボタンを押したのと同じ動きになる（録音前なら開始、録音中なら一時停止・再開、ほかのセッションを開いていれば録音中のセッションに戻る。押せない理由があればボタンと同じトーストを出す）。録音停止ボタンにはショートカットを付けない（取り返しがつかないため）。
  - 効かないのは、文字を入力している途中（input・textarea・select・contenteditable にフォーカスがある・IME で変換中）、モーダル・ダイアログ・シートが開いているとき、キーを押しっぱなしにしたときの繰り返し。
  - キーは全体設定の `display.micShortcut`（5.3 節）。設定モーダルの「表示・その他」で、欄を押してからキーを押すと、その組み合わせが入る。修飾キー（Ctrl・Alt・Shift・Meta）を 1 つ以上含むものだけ受け付ける（Esc でやめる）。「既定に戻す」と「使わない」も選べる。キーは入る文字ではなくキーの位置（`KeyboardEvent.code`）で比べるので、キーの配列や Mac の Option で入る文字が変わっても同じキーになる。 キーは `key`（入る文字）ではなく `KeyboardEvent.code` で比べる（キーの配列・IME・Mac の Option で `key` が変わっても同じキーとみなすため）。
  - 既定のキーは、Chrome・Edge・Safari と Windows・macOS の既存のショートカットとぶつからないものとして選んだ（Ctrl・⌘ との組み合わせはブラウザが多く使う。Alt+Shift だけを押すと Windows の入力言語が切り替わることがあるが、M と一緒に押せば切り替わらない）。
  - PC のマイクボタンのツールチップに、今のショートカットを出す（`aria-keyshortcuts` も付ける）。
- 文字起こしは、文字送りの演出で流れるように表示する。
- 画面上部の切り替えタブで「文字起こし」と「要約」の表示を切り替える。
- 録音を終えたセッションで録音ファイルが残っていれば（`files.recording`）、切り替えタブの下に再生バー（ブラウザの audio）を置く（どちらも上のバーの中。下の「切り替えタブは…」を参照）。文字起こしの行の時刻を押すと、その位置から再生する。録音中のセッションと、録音ファイルが消えた（保存期間を過ぎた・変換前）セッションでは、再生バーを出さず、時刻も押せない。読み込めなかったとき（開いた後に消えたなど）も再生バーを消す。
- **複数の音源（#241。6.16 節）**: 音源が 2 つ以上のセッションだけ、次のものを出す。音源が 1 つのセッションの見た目は変えない。
  - **行の音源の印**: 文字起こし（リアルタイム・浄書済みの両方）の行の時刻の横に、どの音源から出た行かを小さい札で出す（「音源 2」。title と読み上げは音源の名前つきで「音源 2（iPhone）」）。音源ごとに色を変えるが、話者の札（`display.showSpeakers`）とは形を分けて、話者と取り違えないようにする（音源は話者ではない）。#357 では、話者の札（塗りの四角）に対して、音源の札は枠線の丸い札にした。音源の分からない行（ほかの端末が参加する前の行は `source` が付かない・`lineSources` が行の数より短いときの足りない行）は主の音源（音源 1）とみなして札を出す。札の数字は等幅にして、本文の書き出しをそろえる。札は置き換え（6.13 節）で選ぶ文字には入れない。
  - **音源ごとの partial**: 録音中は partial を音源ごとに 1 つずつ持ち、最後の行の下に、話し始めた順（`segment` の順）に並べて出す。それぞれに行と同じ音源の札を付ける。final が届いたら、同じ `segment` の partial を消して行を足す（行は届いた順。6.16 節）。
  - **再生する音源の切り替え**: 再生バーの横に、再生する音源を選ぶメニューを置く（既定は主の音源）。切り替えても再生位置（主の音源の時刻）は保ち、ほかの音源のずれ・ドリフト（5.5 節の `sources`）で、その音源の録音ファイルの位置に直して再生する。行の時刻を押したときは、その行の音源に切り替えずに、選んでいる音源で再生する。その時刻にその音源の録音がない（参加する前・抜けた後）ときは「この時刻の録音はありません」と出す。
    - #371 で作った。録音ファイルは `GET .../recording?source=<音源 ID>`（7.1 節）。メニューに並べるのは、録音ファイルの残っている音源（セッションの `files.sourceRecordings`）だけ。`files.sourceRecordings` がない（古いサーバー・ほかの音源の録音が残っていない）ときはメニューを出さず、主の音源だけを再生する。メニューのボタンは「音源 2」だけ、開いた一覧は「音源 2（iPhone）」（名前がない音源は種類）。メニューがあるときは、狭い画面でシークが消えないよう、メニューと再生速度を再生バーの次の行に回す。
    - 録音がない時刻は、行の時刻を押したとき・切り替えたときに再生を止めて、再生バーの下に「この時刻の録音はありません」と出す（再生を始めたら消す）。参加した時刻のすぐ前（1 秒未満。行の時刻は秒で切り捨てのため）は、その音源の録音の頭から再生する。再生中の行の印は、主の音源の時刻に直して付ける。
    - ほかの音源の録音を読み込めなかったときは、主の音源に戻して「音源 2 の録音を読み込めません」と出す（主の音源を読み込めなかったときは、今までどおり再生バーを消す）。
  - **音源の一覧**: 文字起こしのタブの上（使ったモデル・話者の数を出すところ）に、音源の数を出し、押すと音源の名前・種類（録音した端末 / 参加した端末 / ファイル）・参加していた時間を一覧にする。#357 では「共有」の横に「音源 N つ」のボタンを置き（行の札の「音源 2」は音源 ID なので、数は「つ」で数えて取り違えないようにする）、押すと一覧を出す。名前がない音源（主の音源など）は、名前の代わりに種類を出す。録音を終えたら、録音中の一覧からフロントマターの一覧に取り直す（録音している端末は最終要約ができたとき、見ている端末は録音を終えたとき）。参加していた時間は主の音源の時刻で、主の音源は録音の長さ全体、参加した端末は `joinedSec`〜`leftSec`（抜けていなければ終わりまで）、ファイルは「ファイル全体」。録音中は時間の代わりに、つながっているか（つながっています / 切れています / 抜けました）を出す。
  - **録音中の参加**: ほかの端末で録音中のセッションを見ているとき（#238）、マイクボタンを「この端末のマイクで参加」にする。押すとマイクの許可を取り、参加する（7.2 節の `join`）。参加している間は、マイクボタンを「参加をやめる」にし（押すと `leave`）、マイクの音量と「参加中」を出す。一時停止・録音停止のボタンは出さない（録音の操作は録音している端末だけ）。参加できるかは押す前に `watching`・`sources` の `join` で分かるので、サーバーが参加に対応していない（`join` がない）・つながっている音源が上限（`recording.maxSources`）に達している（`reason: limit`）・参加を切っている（`reason: disabled`）ときは、ボタンを押せなくして理由を出す（7.2 節）。空いたら（`sources` で `join.available` が戻ったら）押せるようにする。
    - #357 で、#356 の最低限のボタン（タイトルの下の「このマイクで参加」）をマイクボタンに移した。参加している間は、マイクボタンの上に「音源 N として参加中」（返事待ちは「参加しています…」、つなぎ直している間は「ホストにつなぎ直しています」）を出し、ボタンの後ろの輪をマイクの音量で広げる（録音中と同じ）。押せないときは、マイクボタンの上に理由をいつも出す（タッチでなくても）。見始める返事（`watching`）が届くまでは、押せなくして理由は出さない。参加できるとき・参加しているときは「この端末では閲覧専用です」を出さない。
  - 録音している端末には、参加している音源の一覧（名前・つながっているか）を、録音の状態の表示の横に小さく出す。参加した端末が切れたら、トーストで知らせる（録音は続いていることも書く）。#357 では、`kind: join` で抜けていない音源を「● 音源 2（iPhone）」の小さい札で出し、切れている間は点を黄色にして「切れています」を足す。トーストは「音源 2（iPhone） との接続が切れました。録音は続いています」（つながっていた音源が切れたときだけ）。
  - **複数のファイルから作る**: 新規セッション画面の「音声ファイルから作る」で複数のファイルを選んだ（ドロップした）ときは、「1 つのセッションにまとめる（同じ場を複数のマイクで録ったもの）」と「別々のセッションにする」を選ばせる。まとめるときは、主の音源にするファイルを選べるようにする（既定は 1 つ目）。ファイルの数が `recording.maxSources` を超えたとき・サーバーが対応していない（`/api/settings/options` に `recording.maxSources` がない）ときは、「1 つのセッションにまとめる」を押せなくして理由を出す。
    - #357 では、選んだときにダイアログを出す（まとめられるなら「まとめる」が既定）。まとめるときは、主の音源のファイルを `upload?sources=N` で送り、残りを 1 つずつ `sources/upload` で送る（進み具合は「<ファイル名>（2/3）」）。残りのどれかが送れなければ次へ進み、送り終えてから、送れなかったファイルと「届いた N 個のファイルで、30 分後に作ります」を知らせる（ホストは最後にファイルが届いてから 30 分待ち、届いた分だけで浄書する。6.16 節）。`404` が返ったら残りは送らず、1 つ目のファイルだけのセッションになったことを知らせる。どちらのときも「まとめて作ります」の知らせは出さない。別々にするときは、1 つずつ今までのアップロードをする。
- **再生速度（#268）**: 再生バーの右に、今の速度のボタン（「1.25×」）を置く。押すと、基本の速度（1・1.25・1.5・1.75・2）のボタンと、数値で指定する入力欄を出す。数値は 0.5〜3、0.05 刻みで、範囲外は丸める（入力を確定したとき、Enter かフォーカスが外れたとき）。選んだ速度は端末ごと（localStorage）に覚え、ほかのセッションを開いても、開き直しても保つ。録音を読み込むたび・再生を始めるたびにかけ直すので、文字起こしの行の時刻を押して飛んだときも変わらない。 `audio` は `src` が変わると作り直されて等速に戻るので、読み込みのたびにかけ直す。
- 浄書済み文字起こし（6.9 節）があれば、文字起こしのタブではそれだけを出す（要約と同じ。リアルタイム文字起こしに戻す切り替えはない）。なければ（録音中・作っている途中・作らない設定・作れなかったとき）リアルタイム文字起こしを出し、作り終えた瞬間に浄書済み文字起こしに替わる（#145）。横に、使ったモデル・話者の数・作った日時を出す。話者を分けた行は、全体設定の `display.showSpeakers`（既定はオフ、#146）がオンのときだけ「話者 1」などを色付きの札にし、話者の数も同じときだけ出す（オフでも文は出し、選んで直せるのは文の部分だけ）。話者分けのモデルを使えなかったときは、そう書く。どちらの文字起こしでも、文字を選んで正しい語に直せる（6.13 節）。作っている間（`status` の `transcribing` に入っているか、GPU キューに `finalTranscript` のジョブがあるとき）は「浄書中…」（再生成のときは「浄書済み文字起こしを再生成しています…」）と出す。
- **浄書済み文字起こしの再生成（#124）**: 要約の再生成と揃える。録音を終えていて録音ファイルが残っているセッションに「<今の Whisper のモデル> で再生成する」ボタンを出す（浄書済み文字起こしがまだなければ「浄書する」）。WhisperX のないサーバー（`/api/settings/options` の `whisper.finalTranscript` が false）では出さない。録音ファイルがなければ、再生成できない理由を出す。版が複数あれば、選んで切り替えられる。既定は、今の全体設定の Whisper のモデルで作ったうちいちばん新しいもの（なければモデルを問わずいちばん新しいもの）。表示しているものが今のモデルのものでなければ「<モデル> の浄書済み文字起こしはまだありません」と出す（モデルを変えても、要約と違って自動では再生成しない。数分かかるため）。再生成したら、要約も再生成するかをトーストで聞く（勝手には再生成しない）。録音中や、ほかのジョブを実行している間に押しても、録音が終わってから・キューの順番で作る。
- **要約のコピー（#203）**: 最終要約の横の「コピー」ボタンで、表示している版の要約を Markdown のまま（ファイルの本文と同じ文字列で）クリップボードに入れる。要約（最終要約・リアルタイム要約）の一部を選んでコピーしたときも、テキストとしては Markdown（見出し・箇条書き・表・太字・コードブロック。数式は元の TeX を `$…$`・`$$…$$` で）を渡す。HTML も今どおり渡すので、HTML で貼るアプリ（Notion など）では見た目のまま貼れる。選んだ範囲の端が数式やコードブロックの途中なら、それごとコピーする。範囲が要約の外にはみ出していれば、ブラウザの普通のコピーになる。
- **共有（#335）**: 文字起こしタブの上と、要約の横の「共有」ボタンで、OS の共有機能（Web Share API）を使って ChatGPT などほかのアプリに渡す。外部 AI の認証や API キーは持たない。
  - 渡すものは、要約・文字起こしの全文・要約と全文から選ぶ（ない方は選べない）。要約は表示している版、文字起こしは表示している世代（最終の文字起こしがあればそれ）。任意の「追加の指示」は本文の先頭に付ける。本文は Markdown で、タイトルの見出しのあとに「要約」「文字起こし」（各行は `[時刻] 本文`）が続く。
  - 本文が 8000 文字以下なら `navigator.share({ title, text })` でテキストとして渡す。それより長いときはファイル（`navigator.canShare({ files })` が通るとき。Chrome が `.md` を共有に渡せないので、共有に渡すファイルは `.txt`・`text/plain`。中身は Markdown のまま）で渡し、ファイルを渡せない環境ではテキストで渡す。長いテキストは、受け取るアプリで切れたり貼り付け欄に入りきらなかったりするため。
  - `navigator.share` がない・安全なコンテキストでない（LAN の http など）ときは「共有」を出さず、「コピー」と「.md をダウンロード」だけを出す（共有できるときも両方出す）。共有シートを閉じたとき（`AbortError`）はエラーにしない。ほかの失敗はトーストで知らせる。
  - クラウド版も同じ画面（同じ部品）を使う。

  - **Mac の配布版（`.app`。#292。`docs/install-mac.md`）だけ**: メニューの「終了」の上に「ログイン時に起動」（チェックの付く項目。既定はオフ）を出す。オンにすると `~/Library/LaunchAgents/io.github.studio-takumi.remote-whisper.plist`（`.app` の起動用のスクリプトを `--login` 付きで動かす。ブラウザは開かない）を置き、オフにすると消す（動いているサーバーは止めない）。plist が今の `.app` 以外（移す前の場所）を指していたら、チェックを外して出し、押すと今の場所で書き直す。書けなければ通知で知らせる。開発（`uv run`）では出さない。
  - Mac の配布版は、Finder などから開くと起動したら画面をブラウザで開き（`--open-browser`）、動いているときにもう一度開くと（LaunchServices の「開き直す」イベント）画面をブラウザで開く。Dock にはアイコンを出さない（`LSUIElement`）。
